# V4.0 verification

## Collection and offline recovery

The collector runs in the Python server, with a single Finnhub connection
and bounded reconnect delays. Browser updates read already stored trades.
The public crypto feed uses periodic snapshots and history in the server,
and the Crypto view retains its exchange stream while visible. The app
preserves provider timestamps and locally captured volume. The captured
sample can differ from market-wide trades and candles.

In a disposable test database, the real Finnhub stream captured a
positive-volume trade before an HTTP server or browser opened. The trade
was already in SQLite. The app then displayed the captured trade timestamp
and collector state. With upstream calls blocked in the isolated server,
the browser reopened a 250-close Apple chart, 30 saved news articles and
the 500-close learning report. After the tab closed and the simulated
outage ended, the server reconnected and stored a newer real trade.
Fixture checks covered a failed connection followed
by successful capture, a new worker reading the same saved history,
duplicate daily session labels, malformed frames and keeping the Finnhub
key outside browser responses.

The optional macOS login job was checked as a configuration. It was not
activated on the user's Mac. Physical sleep and a full macOS login were
not exercised. Existing data and credentials were not packaged.

## Learning report

The lab fits standardized ridge regressions on five daily-price factors.
Each fold trains only on outcomes known at the forecast anchor. Evaluation
anchors are spaced by the target horizon. The earlier half of the
walk-forward cases is used for calibration and the later half for the
independent check. A learned scenario is released only if both blocks beat
the unchanged-price baseline on mean absolute return error. The tests show
the candidate's original scores even when its scenario is withheld.
For a passing candidate the final fit uses all available earlier outcomes,
and the illustrative range uses calibration residuals. The scores belong
to the walk-forward candidate, not a promise about the final fitted model.

The source requires consecutive New York sessions. The reader now
collapses multiple provider timestamps for one session and prefers the
ticker daily bar's midnight label. Stale anchors and extreme jumps withhold
forecasts. The cache keys reports to the method and the actual observations.

Real-data spot checks used saved closes for Apple, AMD, Nvidia and Take-Two.
Apple had 500 consecutive closes. The other three had about 300 each at
the initial check. No learned scenario was promoted in those runs. Some
20-session cases lacked enough tests, and the other candidates failed at
least one baseline comparison. This is a useful result about the evidence
available for this model and these samples.

The purple chart scenario remains distinct. No forecast accuracy claim
extends beyond the listed sample and method.

All 503 Python tests passed in each of three rounds. All 35 JavaScript test files passed. See the bundled result files for counts and timings. The
archive is checked for CRC, source-byte agreement and executable launchers.
