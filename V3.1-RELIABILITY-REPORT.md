# Market Desk Reborn V3.1 — reliability release

V3.1 preserves the V3.0/V3.0.1 feature set and concentrates on saving, recovery,
validation, concurrent requests and usable layouts. It adds repeatable test
launchers and repairs failures found during the tests.

## What was fixed

| Failure found | Result in V3.1 | Evidence |
|---|---|---|
| Damaged latest workspace had no usable automatic fallback | Reads the previous valid generation; retains damaged evidence on a later save; tells the user to review recent changes | Fault injection, browser recovery of a labelled test note, persistent recovery notice |
| Imports could partly write browser records after a quota error | Validates first, restores affected previous records if writing fails, and accepts no partial import | Failure at each of four write positions; unrelated browser records preserved |
| A burst of local HTTP connections could reset a request | Larger pending connection queue, retaining loopback-only access | Parallel request sweep; repeated full-suite runs |
| Non-object request bodies or wrong V3 record shapes could produce a server error | Rejects them as invalid input; rejects non-finite JSON numbers | Malformed bodies across 11 mutating routes; server remains responsive afterward |
| Some Finnhub open/close values outside the high/low range could pass | Rejects inconsistent OHLC, oversized volume and future timestamps | Provider-boundary cases |
| Fractional trade timestamps could be truncated | Rejects them rather than creating a plausible whole-millisecond event | Recording boundary test |
| Malformed cached price bars could be plotted or break a response | Withholds unusable saved bars without deleting the database | Inconsistent price/timestamp cache fixtures |
| Non-text symbols could become assets named NONE or TRUE | Requires a text symbol | Symbol validation cases |
| Forecast action overflowed a phone screen | Wraps the controls within the available width | Browser sweep at 390 × 844 and targeted recheck |

## Automated coverage

The exact final counts, durations and UTC time are in
[V3.1-AUTOMATED-RESULTS.json](V3.1-AUTOMATED-RESULTS.json). Three consecutive
full Python passes are required by the repeat runner. These are repeated
executions of the same tests, not three times as many unique tests.

The JavaScript runner covers 26 test files (listed in
[V3.1-JAVASCRIPT-RESULTS.json](V3.1-JAVASCRIPT-RESULTS.json)), including the earlier UI and model
checks and new storage/transport/race tests. Every site script also passed
syntax checks. Python and JavaScript results describe different suites and
should not be added as if each JavaScript file were one assertion.

New generated cases use fixed seeds for reproducibility:

- 250 hypothetical FIFO/cash-conservation ledgers.
- 250 cash-flow scenarios that must not create investment performance.
- 100 cumulative statement sets, including missing-period withholding.
- 100 AI-source mutation cases, each rejecting an invented number and quote.

Other checks include failed fsync/replacement, abandoned temporary files,
invalid/oversized backups, previous-generation recovery, 80 concurrent-workflow
saves/readbacks, 80 parallel calculation requests, 2,000 concurrent recorded
price writes, 5,400 observations exercising per-symbol retention, duplicate
observations, complete rollback of failed database batches, ledger capacity,
exact-date benchmarks, source/currency separation, offline restart, chronological
forecast backtests, permissions, request-origin restrictions, calendar/DST,
alerts, reports, reduced motion and navigation cancellation.

Tests use temporary homes and labelled synthetic fixtures. External provider
requests are blocked by the Python regression runner. No personal workspace,
keys, real orders, paid API requests or new model downloads are needed.

## Browser checks

All 22 destinations opened at 1280 × 900 and 390 × 844. The phone sweep found
and led to the forecast-control repair; its width was checked again afterward.
No browser console errors were observed in the sweep. Large tables retain
internal scrolling. This is a Chromium in-app-browser check with a simulated
phone viewport, not a claim of testing every browser or physical device.

An isolated preview deliberately damaged its disposable latest workspace.
The previous labelled research note loaded, the app saved again, the original
damaged bytes were preserved, and the recovery notice remained visible in
Settings. Genuine saved public price history continued to show original dates
and gaps. Provider credentials were absent from the preview.

## Recovery and storage

Normal saves retain one previous valid `workspace.previous.json`. If an
existing latest workspace is damaged, a subsequent save preserves its bytes
as `workspace.damaged.json` and keeps the prior valid generation. These files
stay private beside the existing local workspace. They are bounded recovery
copies, not an unlimited version history or a replacement for an external
backup. The workspace size limit remains 2.5 MB per file; two retained copies
can add up to about 5 MB. Market price databases and model weights are separate.

An interrupted write before atomic replacement leaves the last committed
primary intact in the tested failure paths. Tests cannot reproduce every real
hardware, filesystem or power-loss failure. If both copies are damaged, the
app reports the problem and leaves browser records available; it does not
claim to recover data that no longer exists.

## Repeat the checks

1. Open **Run Reliability Tests.command** in the extracted folder.
2. It runs three isolated Python passes and saves `Reliability-Test-Report.json`.
3. Optional, with Node.js already installed: `node tests/run_javascript.cjs`.
   Node is not needed to use Market Desk or to run the Python checks.
4. In the app, Settings → **Check saved files** performs a quick read-only check
   of the actual local database, assets, backup integrity and permissions.

The repeat runner was checked on Python 3.12.5 on this Mac. An output report
written next to the app contains test results, not provider keys or market data.

## Limits of the result

This release does not certify future provider uptime, plan access, investment
accuracy, AI semantic truth or unrestricted global data coverage. Numeric and
citation rejection tests are narrower than checking the meaning of every AI
sentence. No live model generation or new paid-provider soak was performed
for this reliability release. Existing data coverage, free-tier pacing, local
AI safeguards and the rule that nothing runs while the Mac/app is off remain.
