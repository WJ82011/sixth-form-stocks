# V3.5 verification

## Automated checks

[V3.5-AUTOMATED-RESULTS.json](V3.5-AUTOMATED-RESULTS.json) records three passing
rounds of **466 Python tests**. These repeat the same suite, not 1,398 unique
tests. [V3.5-JAVASCRIPT-RESULTS.json](V3.5-JAVASCRIPT-RESULTS.json) lists **32
passing JavaScript test files**. All browser scripts parse. Python tests use
throwaway homes/databases and block real provider calls.

New Python cases cover partial-draft validation, company/source separation,
unknown-field removal, future/nonfinite/bounded inputs, atomic backup rejection,
profit-bridge reconciliation, negative profit, headline filtering, calendar
holidays/early closes/DST, unsupported years, as-issued receipt integrity,
prospective creation, duplicate-anchor refusal, actual stored timestamp units,
stale/preclose withholding, missing target dates, scoring against an identical
baseline target, revised prices, frozen assessments after cache pruning,
malformed archive IDs, archived-score inclusion and non-overlapping cohorts.
The scenario path is checked for user-hypothesis labelling, preserved question
length, unsupported-number rejection and use of the existing grounded engine.
Existing V3.4 and earlier financial, recovery, concurrency, import, chart,
request-protection and other feature regressions remain in the suite.

New JavaScript cases cover restart recovery, separate company copies, stale
windows, quota failures, retained damaged JSON, bounded storage, negative-value
waterfalls and escaping. Startup fixtures verify that automatic workspace
restoration does not overwrite damaged/newer local drafts and that full backup
snapshots include recovery records. New controls avoid the retained navigation
attribute, preventing the earlier cross-feature button collision.

## Browser and real local-engine checks

A separate temporary preview used copies of genuine saved public provider,
SEC and FRED records. Keys were redirected to missing temporary paths. Personal
portfolio positions, notes, reports, private workspace and existing forecast
journal tables were not copied. Test business inputs were explicitly labelled
QA assumptions. No test data or credentials are included in the release.

The following flows were checked in that preview:

- Loaded Take-Two and Apple sources, with actual dated filing/quote coverage
  and the new known/investigate/missing research cards.
- Recovered a partially completed analysis, a chosen case and unfinished
  evidence-entry text after a browser reload and a server restart.
- Kept separate company recovery copies. A completed analysis save retained
  its recovery copy and unsubmitted source-entry text.
- Previewed a user-entered five-percent selling-price hypothesis. The original
  case stayed unchanged before Apply; applying updated only the chosen case
  and added a labelled assumption. This was a QA scenario, not a Take-Two view.
- Inspected the native profit chart, case selection and detailed figures.
  Its components reconciled to the business calculation.
- Ran the installed `qwen3.5:4b` model once through the new assistant flow.
  It returned an accepted explanation with supporting source excerpts and
  labelled the numerical input as a user hypothesis. No number was silently
  applied. This single smoke test is not a semantic-accuracy benchmark or
  guarantee that all generated interpretations are correct.
- Recorded a new Take-Two forecast from genuine saved provider closes at the
  actual local-server time. Its target sessions were still in the future,
  so it showed Waiting and contributed no fabricated resolved result.
  A second attempt for that starting session was refused.
- Archived/restored the forecast without changing page or removing it from
  aggregate accounting.
- Downloaded and inspected a full research backup containing two recovery
  copies plus the saved analysis, and a separate journal audit file containing
  frozen model inputs and a still-pending outcome. QA downloads were moved
  to temporary test storage, leaving earlier user downloads untouched.

All 22 existing destinations opened on desktop and at a 390-pixel phone
width. [V3.5-BROWSER-RESULTS.json](V3.5-BROWSER-RESULTS.json) records those destinations.
No document-width overflow was observed. The new chart keeps its
horizontal scrolling inside its own container and offers a text alternative.
Light/dark appearance and the final screenshots were inspected before packaging. Browser checks
use public copied data and demonstrate interface behaviour, not feed uptime.

## Boundaries

No future outcome was observed or invented during this release test. Historical
backtests and prospective results are distinct. The unchanged-price baseline,
uncertainty and possible scoring withholding remain explicit. Directory and
calendar data can become stale, and unexpected closures can leave a target
unscorable. Private journal records are local records, not independently
authenticated exchange data or proof of profitable trading.

The ZIP preserves executable Mac launchers, excludes runtime data/keys/model
weights, and is checked for CRC, source-byte agreement and known-key exclusion.
See PACKAGE-SIZES.txt for final size and V3.5-QUICK-GUIDE.txt for opening steps.
